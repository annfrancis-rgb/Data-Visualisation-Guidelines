aiRA data visualisation companion v0.2

The charts, tables and dashboards aiRA draws, specified the way the aiRA Design System specifies everything else. This release covers the core chart set, the specialist charts, the analytics settings and table patterns Power BI users expect, and the three parts every chart shares.

5chart blocks the design system names today
10core charts, bar and line included
3shared parts: card, key, tooltip
9specialist blocks, plus maps as tile grids
5analytics settings and table patterns from Power BI

Every colour, type style, space and radius on this page is a design-system token, read from the live site. Where a chart needs something the system does not have, it is marked Proposed and collected under Proposed tokens. The written rules behind these specs, including integrity, freshness, layouts and platforms, live in the foundations draft.

Toggle Light and Dark in the top bar: every chart re-resolves its tokens. Hover or tap any mark for its tooltip, or tab to a chart and use the arrow keys.

How to use this page

Each block follows the design system's component shape: a live example, when to use it, anatomy with tokens, settings, states, accessibility, copy, do and don't, and an engineering handoff.

An engineerSwitch to Developer view for settings and the handoff snippet. Names marked Proposed are not in the library yet.

Rules every block on this page follows

  • The title is the chart's name. What it shows ("Daily redemptions"), never the finding. The finding goes in aiRA's answer next to the chart, and in annotations and highlights on it.
  • Trust line on every chart: the table aiRA queried and the time the query ran, in the org timezone. Nothing else.
  • Direct labels first. A key only for colour scales, size, collisions and small multiples.
  • Never red on chart marks. Down is --aira-delta-negative orange; red stays for errors.
  • View as table on every chart, and nothing essential only on hover.
  • One colour means indigo. A single series uses --aira-viz-1; channel colours only appear when channels are compared.
  • Hover dims the rest. The active mark keeps its colour and the others fade. No outlines.
  • Org locale for every number: this page's demo org is Indian, so lakh, crore and ₹.

Chart card

ProposedUpdated 2026-09-23Design system owner · Punya Shetty

The frame every chart sits in: title, subtitle, optional key, plot, trust line and actions. It is a composition of AiraCard, so no chart ever needs its own header.

Example

Resize the window: below 480px the columns become horizontal bars, as the chooser requires for narrow space. One highlight (HSR Layout) in --aira-viz-1, the rest in context grey. Every bar is labelled, so there is no value axis.

Use when

Use when

Any chart, on any surface: chat answer, artifact panel, dashboard tile.

Don't use when

A KPI tile. AiraMetricTile has its own anatomy.

Anatomy

PartTypeColourRule
Title--aira-t-label-md--aira-text-primaryThe chart's name: what it shows, as a short noun phrase. Never the finding. One line
Subtitle--aira-t-caption--aira-text-tertiaryMeasure · unit · period · filters
Actions.iconbtn sm--aira-text-tertiaryView as table, copy, download, expand. Borderless, scoped to this chart
KeySee Chart keyOnly where the key rules allow
PlotMarks, axes, annotations
Trust line--aira-t-caption--aira-text-tertiarySource: the table aiRA queried (write_db_100783.points_aira) · As of time in org timezone. Nothing else. Never optional
Surface--aira-surface-artifact-card-bg--aira-radius-md, 1px --aira-border-default, padding --aira-sp-4, parts spaced --aira-sp-3

States

  • Loading: AiraSkeleton in the plot's shape; title and subtitle already shown.
  • No data: the plot area holds a message and a next step, never a blank chart.
  • Error: plain language and Retry. No codes.
  • Old snapshot: the card offers Re-run when the result is over 24 hours old.

Accessibility

  • The plot is one tab stop with role="img", named by the title and described by a text summary.
  • Arrow keys move between values; each is announced ("3 of 6. Koramangala, 11,910 redemptions").
  • View as table is a real button with aria-pressed.

Do / don't

Do

Name the chart for what it shows: "Redemptions by store".

Don't

Write the finding as the title: "HSR Layout led September redemptions". The finding goes in aiRA's answer.

Do

Say the period is partial when it is.

Don't

Drop the trust line to save space.

Chart key

ProposedUpdated 2026-09-23Design system owner · Punya Shetty

A key makes the reader look away, remember a colour and look back. So the first choice is always a direct label; the key is the fallback, and it has three forms.

Direct labels (the default)

Names sit at the line ends in text colour; the dot carries the series colour. Tiers take locked sequential steps by rank (Silver seq-4, Gold seq-5, Platinum seq-6).

Inline key (paired and stacked charts)

EmailPushLine series

A row between subtitle and plot. 8px square swatch for areas, 12×2px line for lines. Label text is neutral, never the series colour.

Scale key (colour scales, always shown)

Under 20%40%60% or more

Heatmaps, cohort grids and filled maps. Low and high ends labelled, and the middle on diverging scales.

When a key appears

CaseKey
One series; bars and columns; donut, waffle, treemap; KPI tiles; sparklinesNone
Several lines; stacked bars; paired bars and dumbbellsDirect labels, or an inline key in the subtitle
Heatmaps, cohort grids, filled mapsScale key, always
Bubble sizeSize key, always
Different kinds of marks together: bars with a line, a shaded band behind a line, coloured bars beside grey onesName every mark type on the chart: a direct label where it fits ("Expected range" on the band), otherwise an inline key
Direct labels would collideInline key
Small multiplesOne shared key for the set

Rules

  • Top-left, between subtitle and plot, in a row. Never at the right: aiRA's surfaces are narrow.
  • In data order (stack order, or lines by last value). Never alphabetical.
  • Clicking an item may highlight that series; it works from the keyboard and never replaces View as table.

Bar chart

Stable blockProposed settingsUpdated 2026-09-23Design system owner · Punya Shetty

The workhorse. Length on a shared baseline is the most accurately read encoding there is, so when the question is "how do these compare", the answer is a bar chart unless something rules it out. AiraBarChart ships today; the variants below are its settings.

Column and horizontal

Columns for up to 12 short categories or for periods; horizontal bars for long labels or more than 12 categories. This example switches by itself below 480px.

Paired

The current period is indigo; the comparison period is context grey, so the eye reads "now" first. Two groups only; more becomes a dot plot or small multiples.

100% stacked

Four channels compared, so channel colours apply here. A single-series bar is always indigo.

Variance

Use when

Use when

Comparing values across categories, or totals across a few periods. The default answer to "which is biggest".

Don't use when

A trend over many periods: use a line. Two or three parts of a whole with a headline total: a donut.

Variants

100% stackedShares compared across groupsProposed setting

With a same-unit lineActual bars with a target or average lineProposed setting

Do / don't

Do

Sort by value unless the categories have their own order (time, tier).

Don't

Start the value axis above zero. A bar's length is its value.

Do

Keep one colour for one series: indigo.

Don't

Put a number on every bar and keep the value axis as well.

Line chart

Stable blockProposed settingsUpdated 2026-09-23Design system owner · Punya Shetty

The default for anything over time. AiraLineChart ships today; forecast, anomaly markers and moving average are its new settings.

Lines with direct labels

Forecast

More settings, each with its own example: anomaly markers, moving average and reference lines.

Use when

Use when

A measure over time, especially more than 12 periods, or several series over the same periods.

Don't use when

Categories with no order: a line between them implies a connection. Use a bar.

Partial periodProposed patternThe last, incomplete period is marked, never shown as a drop

Rules

  • At least two full cycles of history before forecasting; horizon no longer than a third of the history shown.
  • aiRA's answer states the forecast range, not only the point.
  • Size the chart so the main slope sits near 45°.

Actual against a target, in a single row per item. It replaces the gauge: same answer, a fraction of the space, and rows compare against each other.

Example

Use when

A value has a target, a plan or a benchmark, for one item or several.

Don't use when

There is no target: use a bar. Or the question is about change over time: use a line with a target line.

Waterfall chart

ProposedUpdated 2026-09-23Design system owner · Punya Shetty

Explains what moved a total from one value to another. The standard answer to "why did revenue change?"

Example

The value axis starts at ₹36L because a waterfall reads the steps, not the totals from zero. The start and end bars say so with their labels; this is the one bar-like chart where a non-zero start is honest.

Use when

Use when

A total changed between two points and the parts of the change are known: revenue bridge, points liability, member count.

Don't use when

The parts overlap or do not add up to the change. Then show a sorted bar of drivers and say they overlap.

Anatomy

PartTokenRule
Start and end bars--aira-viz-1From the axis floor, labelled with their totals
Up step--aira-delta-positiveFloating, label with + sign
Down step--aira-delta-negativeFloating, label with − sign. Never red
Connector1px dashed --aira-viz-baselineFrom each bar's end to the next bar's start
OrderIncreases first, largest first, then decreases, largest first

States

  • More than 7 steps: group the smallest into "Other changes".
  • A step of zero stays, labelled "0", so the list is complete.

Do / don't

Do

Check that start plus steps equals end, and say so in aiRA's answer when rounding means it does not.

Don't

Colour increases green when an increase is bad, such as points liability. Colour follows good or bad.

Funnel chart

ProposedUpdated 2026-09-23Design system owner · Punya Shetty

Campaign stages from sent to redeemed, as aligned bars on one baseline with the conversion between steps. Never trapezoids: the shape hides the real drop-offs.

Example

One series, so one colour: aiRA indigo, --aira-viz-1. The channel is named in the subtitle; channel colours only appear when several channels are compared.

Use when

Use when

Members move through ordered stages and each stage is a subset of the one before.

Don't use when

Stages are not subsets (people can skip one). Use a bar chart of each stage and say so.

Anatomy

PartTokenRule

  • Title: the campaign and "funnel". The end-to-end rate or the biggest drop goes in aiRA's answer.

Do

Show the attribution window in the subtitle.

Don't

Compare two campaigns in one funnel. Use small multiples, or a table of step rates.

Heatmap and cohort grid

ProposedUpdated 2026-09-23Design system owner · Punya Shetty

Two categories and one measure, shown as a grid of cells coloured by value. The cohort variant is the retention triangle every loyalty team asks for.

Example: cohort grid

Cell text switches between --aira-text-primary and --aira-text-inverse by computed contrast on each step, in each theme. Empty cells are months that have not happened yet, not missing data.

Use when

Use when

Rows and columns are both categories (day by hour, store by month, join month by months since).

Don't use when

One of the axes is continuous and the exact values matter: use a line or small multiples.

Scatter chart

ProposedUpdated 2026-09-23Design system owner · Punya Shetty

Two measures across many items, to see whether they move together and which items stand apart. The bubble variant adds a third measure as size.

Example

Highlight and grey: the members the annotation names are in --aira-viz-1, everyone else in context grey. Dots are 6px with a 1px surface ring so overlaps stay visible.

Use when

Use when

Many items, two measures, and the question is about relationship or outliers.

Don't use when

One measure is time: use a line. Fewer than about 15 items: use a table or dot plot.

Donut and pie charts

ProposedUpdated 2026-09-23Design system owner · Punya Shetty

Use sparingly. Angle is one of the weakest encodings people read, so a donut or pie is only for two or three parts when the rough proportion is the point. Past three parts it becomes a sorted bar, a 100% stacked bar or a waffle. The donut is preferred: its centre holds the headline total.

Example

Use when

Use when

Two or three parts, the rough split is the point, and there is a total worth showing.

Don't use when

Four or more parts, or parts that are close in size: angle is too weak to compare them. Use a sorted bar.

Anatomy

PartTokenRule
Segments--aira-viz-1, -2, -3 in order of size1.5px surface gap; start at 12 o'clock, clockwise, largest first
Labels--aira-t-label-sm, --aira-text-secondaryName and share beside each segment. No key
Centre--aira-t-h2 + --aira-t-captionThe total, compact, with its unit word
HoleInner radius about 62% of outer

Rules carried from the design system

  • Two or three slices only. The agent never draws a fourth; it draws a sorted bar and says why in one line.
  • Never 3D, never an exploded (pulled-out) slice, never a second ring.
  • A single insight per chart.
  • Pie only when there is no total worth showing; otherwise the donut.

Do / don't

Do

Say so in aiRA's answer when shares do not sum to 100% after rounding.

Don't

Use a pie for close values such as 34%, 33% and 33%. Nobody can see the difference; use a bar.

Test result

ProposedUpdated 2026-09-23Design system owner · Punya Shetty

The result of an A/B or campaign test: each variant's difference from control, with its likely range. It says plainly when a result could be chance.

Example

Use when

Use when

Any randomised comparison of a variant with a control.

Don't use when

A before-and-after comparison without a control group. That is a change over time, not a test; use a line and describe association.

States

StateMarkCopy
Clear resultRange fully on one side of zero; --aira-delta-*"Variant B lifted redemption by 2.1 pts (likely 1.2 to 3.0 pts)"
Could be chanceRange crosses zero; context grey"No clear winner yet. The difference could be chance."
Still runningContext grey, progress in the subtitle"Test running, day 5 of 14. Results so far are not reliable."
Too few membersContext grey"1,240 members per group so far; about 4,000 needed to be sure."

Anatomy

PartTokenRule
Zero line1px --aira-text-secondaryStronger than gridlines: it is the "no effect" line
Range2px line with end capsThe 80% likely range; the level is in the tooltip
Point10px dotThe measured lift
Verdict--aira-t-label-smRight column: the lift, or "Could be chance"

Copy

  • Say "likely range", not "confidence interval"; "could be chance", not "not statistically significant". Technical terms go in the tooltip and the SQL tab.
  • Never declare a winner early because a running result looks good.

Slope chart

ProposedUpdated 2026-09-23Design system owner · Punya Shetty

Change between exactly two points, for many items at once. The angle of each line is the change.

Example

All lines are indigo: direction is already carried by the slope and the signed label. Colour by up or down only when up is always good; here a shrinking Base share is good news too.

Use when

Use when

Exactly two points in time (or two conditions) and several items.

Don't use when

Three or more points: use a line or bump chart. One item: a KPI tile with a delta.

Anatomy

PartTokenRule
